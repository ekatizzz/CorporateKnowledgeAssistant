## О проекте

**БАРС-Помощник** — Telegram-бот для сотрудников БАРС Груп, предназначенный для поиска ответов во внутренней корпоративной документации. Проект реализован как ассистент первой линии поддержки и использует подход **Retrieval-Augmented Generation (RAG)**: сначала система находит подходящие фрагменты документов, а затем передаёт найденный контекст языковой модели для подготовки ответа.

В базу знаний входят инструкции и материалы по корпоративным системам и процессам, в том числе БАРС-Офис, бизнес-процессу «Командировка», реестру мебели, Garantexpress, Docsvision и другим внутренним инструментам.

Основной принцип работы — отвечать на основании найденных материалов. Если в базе знаний нет достаточной информации, ассистент не должен придумывать ответ: он сообщает, что не смог найти подтверждение, и предлагает обратиться к оператору.

## Возможности

### Поиск по корпоративной документации

- Поиск по внутренним документам PDF и DOCX.
- Семантический поиск по смыслу пользовательского вопроса.
- Формирование ответа с опорой на найденные фрагменты документации.
- Использование истории диалога для обработки контекстных вопросов.
- Предоставление ссылок на документы, если они доступны через файловый сервис.

### Работа с изображениями

- Приём изображений и скриншотов от пользователей в Telegram.
- Анализ интерфейсов и изображений с помощью vision-модели.
- Обработка изображений, извлечённых из документов.
- Использование OCR для распознавания текста на изображениях.

### Контроль качества ответов

- Проверка релевантности найденного контекста.
- Отказ от уверенного ответа, если в базе знаний нет достаточных подтверждений.
- Fallback-сценарий с предложением обратиться к оператору.
- Обработка ошибок взаимодействия с API и языковой моделью.

### Авторизация и поддержка

- Привязка Telegram-аккаунта к учётной записи сотрудника.
- Разделение пользовательских и административных возможностей.
- Передача вопроса оператору.
- Настройка списка администраторов и часов работы поддержки через переменные окружения.

### Обратная связь, аналитика и статистика

- Сбор данных о взаимодействии пользователей с ботом.
- Сохранение оценок ответов и обращений.
- Выявление вопросов, на которые база знаний не смогла дать ответ.
- Подготовка статистических показателей для оценки качества работы ассистента.
- Визуализация аналитических данных и выявление проблемных сценариев.
- Настройка часового смещения для корректного отображения статистики.

### Управление базой знаний

- Загрузка и обработка корпоративных документов.
- Извлечение текста, таблиц и изображений.
- Подготовка фрагментов и их индексация в векторном хранилище.
- Обновление базы знаний при добавлении новых материалов.

## Как работает ассистент

1. Сотрудник отправляет вопрос или изображение Telegram-боту.
2. Бот обрабатывает сообщение и передаёт запрос в API-сервис.
3. API при необходимости получает историю диалога из Redis.
4. Поисковый модуль формирует эмбеддинг запроса и ищет релевантные фрагменты в Qdrant.
5. Найденные фрагменты и контекст диалога передаются языковой модели через Ollama.
6. Модель формирует ответ на основании предоставленного контекста. Если подходящей информации нет, используется сценарий отказа от неподтверждённого ответа.
7. Бот отправляет результат пользователю и предоставляет возможность оценить ответ или обратиться к оператору.
8. События взаимодействия и обратная связь используются для аналитики и статистики.

## Архитектура

Система состоит из Telegram-бота, API-сервиса и инфраструктурных компонентов.

| Компонент | Назначение |
|---|---|
| `bot_service` | Telegram-интерфейс на aiogram: обработчики сообщений, команды, кнопки, FSM, авторизация, обратная связь и взаимодействие с оператором |
| `api_service` | FastAPI-приложение: обработка запросов, координация RAG-пайплайна, работа с документами и аналитикой |
| `Qdrant` | Векторное хранилище фрагментов корпоративной документации и поиск по эмбеддингам |
| `Redis` | История диалогов, контекст и кэширование вспомогательных данных |
| `PostgreSQL` | Хранение учётных записей сотрудников и данных авторизации |
| `Ollama` | Запуск текстовой и vision-моделей; адрес и имена моделей задаются через `.env` |
| `files` | Выдача документов по ссылкам; публичный адрес и секрет подписи настраиваются через `.env` |

### Подготовка документов

`PDF / DOCX` → извлечение текста, таблиц и изображений → очистка и структурирование → разбиение на фрагменты → создание эмбеддингов → сохранение в Qdrant.

При обработке документов парсер учитывает структуру материалов: сохраняет иерархию заголовков, преобразует табличные данные в текстовое представление вида «Ключ: Значение» и очищает повторяющиеся элементы вроде колонтитулов.

### Обработка пользовательского вопроса

`Вопрос` → обработка сообщения → получение истории → поиск в Qdrant → отбор релевантных фрагментов → передача контекста в Ollama → ответ или fallback-сценарий → отправка ответа в Telegram.

## Быстрый старт

### 1. Требования

Перед запуском подготовьте:

- Git;
- Docker;
- Docker Compose;
- доступ к сервису Ollama с загруженными моделями;
- Telegram-бота, созданного через BotFather;
- доступ к Telegram ID чата оператора, если планируется передача обращений.

Для локального запуска моделей через Ollama потребуется достаточно оперативной памяти и свободного места на диске. В конфигурации ниже Ollama доступна контейнерам по адресу `http://host.docker.internal:11434`.

### 2. Клонирование репозитория

```bash
git clone https://github.com/Yushhhik/CorporateKnowledgeAssistant.git
cd CorporateKnowledgeAssistant
```

### 3. Настройка Ollama

Убедитесь, что Ollama запущена и доступна по адресу, указанному в `OLLAMA_BASE_URL`.

В используемой конфигурации заданы две модели:

- `OLLAMA_MODEL=qwen2.5vl:7b` — основная модель;
- `OLLAMA_VISION_MODEL=qwen2.5vl:3b` — модель для анализа изображений.

Названия моделей в переменных окружения должны соответствовать моделям, фактически установленным в Ollama. `host.docker.internal` используется для доступа контейнеров к Ollama, запущенной на хост-машине.

Если модель эмбеддингов загружается из Hugging Face, при `HF_HUB_OFFLINE=1` она должна быть заранее доступна в локальном кэше. Иначе загрузка из сети будет отключена и инициализация модели может завершиться ошибкой.

### 4. Настройка переменных окружения

Создайте `.env` в корне проекта. Если в репозитории есть шаблон `.env.example`, скопируйте его:

```bash
cp .env.example .env
```

Пример конфигурации, соответствующий используемому окружению:

```dotenv
# Telegram
TELEGRAM_TOKEN=your_telegram_bot_token
PROXY_URL=socks5://host.docker.internal:10808
OPERATOR_CHAT_ID=your_operator_chat_id
API_URL=http://app:8000/webhook

# Ollama
OLLAMA_BASE_URL=http://host.docker.internal:11434
OLLAMA_MODEL=qwen2.5vl:7b
OLLAMA_VISION_MODEL=qwen2.5vl:3b

# Режим работы Hugging Face
HF_HUB_OFFLINE=1

# PostgreSQL
POSTGRES_USER=admin
POSTGRES_PASSWORD=change_this_password
POSTGRES_DB=corp_bot
DATABASE_URL=postgresql+asyncpg://admin:change_this_password@db:5432/corp_bot

# Публичный адрес файлового сервиса.
# Оставьте пустым для локального доступа либо укажите доступный извне URL.
PUBLIC_FILES_URL=

# Секрет для подписи ссылок на файлы: задайте длинную случайную строку.
FILES_SECRET=replace_with_a_long_random_secret

# Администраторы Telegram через запятую
ADMIN_IDS=

# Часы работы поддержки, например: пн-пт 09:00-18:00
SUPPORT_HOURS=

# Таймаут ожидания ответа API, секунды
CORE_TIMEOUT=1300

# Смещение часового пояса для аналитики относительно UTC, часы
STATS_UTC_OFFSET=3
```

Замените демонстрационные значения токена, пароля базы данных и секрета на собственные. Значение `OPERATOR_CHAT_ID` укажите в соответствии с Telegram-чатом поддержки. В `ADMIN_IDS` можно перечислить Telegram ID администраторов через запятую.

Для генерации случайного секрета на macOS или Linux можно использовать:

```bash
openssl rand -hex 32
```

Скопируйте полученную строку в `FILES_SECRET`.

**Важно:** не публикуйте `.env` и не добавляйте его в Git. В репозитории следует хранить только `.env.example` с безопасными демонстрационными значениями. Убедитесь, что `.env` добавлен в `.gitignore`.

### 5. Запуск сервисов

Из корневой директории проекта выполните:

```bash
docker compose up --build
```

Для запуска в фоновом режиме:

```bash
docker compose up --build -d
```

Проверить состояние контейнеров:

```bash
docker compose ps
```

Посмотреть логи:

```bash
docker compose logs -f
```

Посмотреть логи отдельного сервиса, например API:

```bash
docker compose logs -f app
```

Остановить сервисы:

```bash
docker compose down
```

Команда с удалением томов удаляет также сохранённые данные сервисов. Используйте её только если действительно хотите очистить данные:

```bash
docker compose down -v
```

Из контейнера бот обращается к API по адресу `http://app:8000`, а к Ollama, запущенной на хост-машине, — по адресу `http://host.docker.internal:11434`. Для доступа с компьютера-хоста используйте опубликованные в `docker-compose.yml` порты. Порт файлового сервиса в конфигурации проекта — `8001`; его публичный адрес задаётся через `PUBLIC_FILES_URL`.

### 6. Добавление документов в базу знаний

Документы для индексации размещаются в каталоге `docs/` либо загружаются предусмотренным в боте административным способом.

Для запуска индексации используйте скрипт `ingest.py` из API-контейнера. Перед запуском проверьте доступные параметры скрипта:

```bash
docker compose exec app python ingest.py --help
```

Далее выполните команду индексации в соответствии с параметрами, которые поддерживает текущая версия `ingest.py`. Например, если скрипт принимает путь к каталогу документов:

```bash
docker compose exec app python ingest.py docs
```

## Конфигурация переменных окружения

| Переменная | Назначение |
|---|---|
| `TELEGRAM_TOKEN` | Токен Telegram-бота |
| `PROXY_URL` | Адрес SOCKS5-прокси для сетевых запросов из контейнера; при ненужности прокси значение можно не задавать, если приложение это поддерживает |
| `OPERATOR_CHAT_ID` | Telegram ID чата или оператора поддержки |
| `API_URL` | Адрес webhook API, используемый ботом; в текущей конфигурации — `http://app:8000/webhook` |
| `OLLAMA_BASE_URL` | Адрес сервиса Ollama; в текущей конфигурации — `http://host.docker.internal:11434` |
| `OLLAMA_MODEL` | Имя основной языковой модели в Ollama |
| `OLLAMA_VISION_MODEL` | Имя vision-модели для анализа изображений |
| `HF_HUB_OFFLINE` | Отключение сетевых обращений Hugging Face при значении `1`; модели должны быть доступны локально |
| `POSTGRES_USER` | Пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL |
| `POSTGRES_DB` | Имя базы данных PostgreSQL |
| `DATABASE_URL` | Асинхронная строка подключения SQLAlchemy к PostgreSQL |
| `PUBLIC_FILES_URL` | Публичный адрес сервиса файлов; оставьте пустым для локального режима или укажите внешний URL/адрес туннеля |
| `FILES_SECRET` | Секрет, используемый для подписи ссылок на файлы |
| `ADMIN_IDS` | Telegram ID администраторов через запятую |
| `SUPPORT_HOURS` | Текст с часами работы поддержки; пустое значение отключает отображение расписания, если так реализовано в приложении |
| `CORE_TIMEOUT` | Таймаут ожидания ответа API в секундах; в текущей конфигурации — `1300` |
| `STATS_UTC_OFFSET` | Смещение часового пояса аналитики относительно UTC в часах; в текущей конфигурации — `3` |

### Примечания к конфигурации

- В `.env` должна быть только одна строка `PUBLIC_FILES_URL`. Если указать её несколько раз, поведение будет зависеть от загрузчика переменных окружения; оставьте одно итоговое значение.
- `PUBLIC_FILES_URL` — это адрес, по которому пользователь сможет открыть документ со своего устройства. `localhost` подходит только для доступа с того же компьютера; для других устройств нужен доступный им IP-адрес, домен или адрес туннеля.
- `FILES_SECRET` должен быть задан случайным длинным значением. При его смене ранее созданные подписанные ссылки могут перестать работать.
- `OLLAMA_BASE_URL` должен быть доступен именно из контейнера приложения. Адрес `http://host.docker.internal:11434` используется для доступа из контейнера к Ollama, запущенной на хост-машине.
- `API_URL` содержит полный путь `/webhook`; не заменяйте его на корневой адрес API, если код бота ожидает полный URL.
- `STATS_UTC_OFFSET=3` означает смещение на три часа относительно UTC. Это не настройка автоматического определения часового пояса.
- `PROXY_URL` указывает на `host.docker.internal`. Убедитесь, что прокси действительно слушает указанный порт на хост-машине и доступен из Docker.
